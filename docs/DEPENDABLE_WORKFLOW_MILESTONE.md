# Dependable personal Study/TDA/Watch milestone

Accepted priority, 2026-10-30: deliver a dependable personal cockpit integrated into the operator's daily routine before allocating substantial effort to exploratory features. Preserve the accepted design language and friction improvements where they materially support correct work; visual polish is not the release criterion.

## Completion means usable journeys

- Study: begin or resume an identifiable investigation, select a clear historical reference, capture examples/images/questions/findings, reflect at a natural pause, and recover the work after restart without reconstructing associations.
- TDA: follow the active plan through mapped chart/pane context and retain the resulting operating context without transcription or scope ambiguity.
- Watch: consult that context, update current AMDX, capture observations and return to the operational anchor efficiently; unknown/blocked/available states remain truthful.
- Recovery: preserve the actual database, images and settings; verify restore on a separate copy; migrations must preserve real records. Backup creation alone is not a tested recovery path.
- Integration: run complete representative journeys with meaningful material, then consolidate the tested draft-PR stack through separately authorized integration/merge work. Individual passing smoke checks do not establish a release.

## Delivery order

1. Preserve real material. Operator reports creating the full workspace archive and retaining originals. Next establish verified recovery and durable working storage; do not relocate path-based image references blindly or require more meaningful work in a disposable location.
2. Durable investigation registry and safe resumption: see `STUDY_INVESTIGATION_CONTINUITY_V0.md`. This is the next implementation contract, with recovery safeguards before testing against real material.
3. Study reference continuity/correction and question capture at the review pause. Prioritize wrong-context prevention over additional cosmetic polish.
4. Integrated Study/TDA/Watch journeys, restart/recovery checks, and planned stack consolidation; inspect actual gaps before adding more features.

Defer full PDM lifecycle, chart reconstruction, advanced drills, analytical recommendations, unrestricted layout configuration and broad cosmetic work until the core journeys justify their inclusion. Highest TradingView subscription may be assumed available for planning; it does not establish API access or integration feasibility.

Keep workload focused: each change should resolve observed friction, protect meaningful work, or close a required workflow gap. Flag scope additions and explain their effect on this milestone. Use short functional checks for changed behavior and natural sessions for usefulness, without repeatedly asking the operator to recreate accepted work. Prior percentage estimates were informal judgments, not measured completion metrics.
